12/08/26, 11:36 am - Fjyci: Client–Server Architecture

In REST, the client and server are separated from each other.
Client is responsible for the user interface and sending requests
Server is responsible for storing data, processing requests and sending responses.
The client does not need to know how the server internally stores or processes data.
Similarly, the server does not need to know how the client displays the information.
Example:
When you use an online shopping application:
Mobile App → Request → Server → Database
The mobile app asks for product details. The server gets the information from the database and sends it back to the mobile app.

Benefit:
Separation of responsibilities
Easy development and maintenance
Client and server can be developed independently

Uniform Interface 
It means that REST uses a standard, consistent and predefined way of communicating between the client and server.

In simple words, all REST APIs follow common rules for accessing and modifying resources, mainly using standard HTTP methods such as GET, POST, PUT and DELETE.

Uniform Interface benefits
Easy to use.
Provides consistency.
Simplifies API development.
Easy maintenance.
Reduces complexity.


Resource-Based – Definition in REST

Resource-Based means that in REST, everything that the client wants to access or work with is treated as a resource. Each resource is given a unique URI (Uniform Resource Identifier) so that the client can identify and access it.

In simple words, REST focuses on “things” or resources rather than actions. The client identifies the resource using a URI and uses HTTP methods such as GET, POST, PUT, and DELETE to perform operations on it.

What is a Resource?
A resource is any piece of information or object that can be stored, accessed, or manipulated through a REST API.
Examples:
Student
Employee
Product
Customer

Benefits – Single Points

Resource-Based:
Easy identification of resources.
Simple API design.
Easy to understand.
Better organization of data.
Easy maintenance.
Resources can be reused.

Cacheable
REST responses can be stored temporarily in a cache.

A cache is a temporary storage location that keeps previously requested data. If the same data is requested again, it can be provided from the cache instead of contacting the server again.

Benefit:
Reduces server workload
Reduces network traffic
Improves response speed
Saves bandwidth
Simple example:
Frequently accessed images, web pages and product information can be cached.

Layered System
REST follows a layered architecture, which means communication can pass through multiple layers between the client and the actual server.
Example  - 
Client
   ↓
Security Layer
   ↓
Load Balancer
   ↓
Cache
   ↓
REST Server
   ↓
Database

Benefit:
Improves security
Improves scalability
Allows load balancing
Makes system easier to manage
Allows caching at intermediate layers
